## 配置清单与保存方式

菜单、内容、媒体、轮播和已有站点身份继续使用现有管理入口。新增外观配置集中为一个可选的结构化站点设置，例如 `themeAppearance`，随现有站点设置批量读取，不另建每页主题设置查询。

该名称和字段结构属于设计提议，实施计划中需细化 API 验证与管理员表单。新增字段需有默认值，旧代码忽略它，新代码在未保存设置时仍能渲染。调用更新接口只提交变更字段，不能用默认值覆盖已有站点身份或轮播内容。

| 编号 | 配置组 | 可配置内容 | 保存位置与边界 |
| --- | --- | --- | --- |
| C01 | 站点身份 | 标题、副标题、Logo、favicon | 已有站点设置，继续使用媒体引用 |

## 数据、缓存与失败处理

1. 内容继续使用现有 collections、bylines、taxonomies 和 Portable Text。URL 用 `entry.id`，评论与关系查询用 `entry.data.id`。查询明确遵循当前 locale，不能把多个语言的同名 slug 混在一起。
2. 菜单使用 `getMenuWithCacheHint`，站点与主题配置使用现有批量站点设置读取。新外观字段由同一次 options 查询返回，不能另发一个“有无主题配置”的探测查询。
3. 文章列表的标签和相关数据继续批量读取。首页最新文章小组件优先复用主查询结果，分类标签仅在操作时获取列表。不能为每张卡片单独请求作者、标签或点赞数。
4. 上下篇、同分类推荐等确有额外数据需要的功能，实施时分别记录匿名请求的新增查询、复用方案与必要性。评审其价值和 query-counts 差异后再接受，缓存命中不免除冷启动查询的审查。
5. 保留 Astro 缓存标签及当前缓存配置。带个性化内容的响应、互动状态、登录与回调不能被公共缓存共享。页面内容与媒体缺失、菜单为空或设置不合法时有可预测的回退。
6. 加载更多与分类切换保留普通链接；并发响应需防止覆盖新选择。失败时保留已有内容并提供重试，只有成功响应才能推进游标。
7. 受权限限制的正文不先输出再隐藏。如加入 X07，必须单独设计全文输出与搜索/RSS/API 的权限一致性。
8. 保留管理员认证、现有会员 Cookie、QQ 回调和下载权限。视觉修改不扩大公开接口的权限。

## 验收证据

- 页面：P01–P18 的正常内容、空内容、长标题、缺失图片和缺失记录场景；未纳入的扩展明确标注。
- 视口：至少检查 `1440×900`、`1024×768`、`768×1024`、`390×844` 和 `360×800`；横向空间受限时不得整页溢出。
- 交互：导航、轮播、分类、分页、搜索、目录、图片预览、点赞收藏和评论的键盘与触摸操作；加载失败、连点和浏览器返回。
- 身份：匿名访客、已登录会员、管理员、待审核评论、关闭评论与未发布内容；公开 HTML 中不出现其他用户的状态。
- 配置：默认值、保存、刷新、清空、未知枚举、超界数值、失效媒体和旧设置；新增管理员界面检查中文与阿拉伯语方向。
- 视觉：保存当前前台与移植预览的同视口截图。未提供实际 WordPress 参考时，只能验收源码默认设计和本规格，不能声称已与指定站点逐像素匹配。
- 行为测试：优先保护排序/筛选与分页、URL 转换、输入验证、缓存隔离和真实交互。不能用“存在某个 CSS 类或配置常量”充当回归证据。
- 代码检查：提交产品代码前按 AGENTS.md 执行根目录 format/build、quick lint、零诊断的 type-aware lint、相关测试以及适用的 typecheck。修改已发布包时增加 changeset；纯站点私有代码不伪造包发布说明。
- 性能：检查匿名路线的查询差异，包括冷启动；只对新增行为带来的变化作必要解释。首次绘制不能依赖全量子比脚本、付费模块或外部字体。

本阶段只产生文档，验证文档格式、路径和清单一致性；未运行产品构建或浏览器验收，不将其记录为通过。

默认博客主题完成的条件是：审阅后确定的 P/F/C 项全部有实现与验收证据，排除项保持关闭，未采用的源码能力有明确差异说明，现有内容和入口通过回归。任何仍未确认的高级功能都不能计入“全主题功能已移植”。

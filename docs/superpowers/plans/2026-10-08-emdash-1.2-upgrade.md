# EmDash 1.2.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the customized EmDash source fork from f0c58f005 to official emdash@1.2.0, preserve custom behavior, verify and deploy.

**Architecture:** Merge the official stable tag in an isolated Git worktree. Keep the custom admin structure and additive core options, adopt upstream pagination and security fixes, and validate forward-only database migrations on a backup before production.

**Tech Stack:** Astro, React, Kumo, Lingui, Kysely, SQLite, Node.js standalone, systemd.

**Spec:** User-approved upgrade flow in this conversation; official packages/core/CHANGELOG.md and packages/admin/CHANGELOG.md for 1.1.0 and 1.2.0; custom behavior in f0c58f005.

## Global Constraints

- Preserve the original workspace and its line-ending-only modifications.
- Preserve admin layout, Chinese translations, message approval, bulk trash operations, .html URLs, custom tags, QQ and media upload behavior.
- Preserve production data and secrets; no old-site data import, deletion, database replacement or migration down.
- Core upgrades add 090_redirect_enable_loop_guard and 091_redirect_artifacts; back up and test before production.
- Use local Git for commit/push, and retain the previous application release for recovery.

## Review Focus

- Bulk selections persist across upstream numbered pages and failed operations keep remaining selections.
- Message editing updates only comments; public submissions remain pending despite moderation hooks.
- Generated content URLs, legacy redirects, canonical, RSS, sitemap and API/media exceptions remain consistent.
- Existing field values, passkeys, encrypted settings and QQ callbacks remain compatible.
- Site identity changes use upstream domain verification and configured-origin behavior, with scoped setting saves.
